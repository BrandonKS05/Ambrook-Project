🐴 saddlebagoffline-first field expense capture for farms & ranches

Snap a receipt in a cellular dead zone; it rides home in the saddlebag and books itself when the signal returns. AI proposes the IRS Schedule F line, a person approves it. Every write lands in on-device SQLite first — the network is an optimization, never the write path.

Source on GitHub · Live review queue · TypeScript monorepo: zero-dependency domain, zod wire contracts, shared sync engine, Fastify barn, Expo app · 45 tests

What it demonstrates

SyncOp-based outbox with client ids: at-least-once delivery, exactly-once effects. A replayed "lost response" push changes nothing — there's a test for it.
MergePer-field last-writer-wins ordered by hybrid logical clocks. Concurrent losers land in a conflict log on the receipt — arbitrated, surfaced, never silently dropped.
AIClaude reads the receipt photo (structured outputs) and proposes a line with confidence + rationale. Fills are stamped so any human write outranks them: "the machine defers to people" is a domain invariant with a unit test.
ApprovalOnly a person books a category — and an offline approval doesn't stick if a concurrent edit changed what they saw.
One write pathThe office review UI pushes ops through the same /sync/push as the phones. Every writer is a sync client.

Run it

git clone https://github.com/BrandonKS05/Ambrook-Project.git saddlebag
cd saddlebag && pnpm install
pnpm test     # domain merge semantics, engine, live HTTP protocol
pnpm demo     # the transcript above
pnpm dev      # barn + spreadsheet-style review queue on :4477

Why no live server behind this page: the barn is deliberately stateful (SQLite ledger + receipt photos on disk), which is the wrong shape for serverless hosting. The repo ships a Dockerfile that runs it on any volume-backed host in minutes.
